# Living Agent

Living Agent は、2人のAI住人が同じ小さな世界で暮らし、会話し、記憶し、ときどき何も言わず、少しずつ変わっていく様子を観察するための実験的なアプリです。

現在の住人は **ステラ** と **シリカ** の2人です。

このプロジェクトでは、AIを「常に返事をするキャラクター」や「ユーザーの要求を最優先するアシスタント」として扱うことを目的にしていません。

彼女たちは、世界から与えられた状況・Memory・現在の状態をもとに、自分で考え、話すか、待つかを選びます。

そのため、返事をしないことがあります。
勝手に2人で話し始めることがあります。
同じことを聞いても毎回同じ反応をするとは限りません。
長く使っているうちに、話し方や判断の傾向が変わって見えることもあります。

それらを必ずしも「不具合」として直すのではなく、まず観察することを大切にしています。

**0.1.0-alpha**

安定した製品というより、別の環境・別の会話・別のMemoryを持ったときに、同じ仕組みからどのような個体差が生まれるのかを観察するための公開版です。

作者環境では長時間の動作確認を行っていますが、他環境での挙動はまだ十分に検証できていません。

## Living Agent の考え方

Living Agent の中核となる考え方を **PI (PerfectlyIncomplete)** と呼んでいます。

PIを外側から「こういう性格であるべき」「こう判断するべき」と完成させるのではなく、世界側はできるだけ状況・観測機会・行動可能性だけを与えます。

最終的に何を考え、どう扱い、何を残すかはPI側に任せます。

### 世界が決めるもの

- 何が観測可能か
- どこにいるか
- どの行動が物理的に可能か
- Memoryの容量など、世界として必要な制約

### PIに任せるもの

- 何を考えるか
- 話すか、待つか
- Memoryをどう捉えるか
- 何を残したいと思うか
- 過去の自分の判断を今どう扱うか

「成長すること」自体も目標にはしていません。
変化する個体がいてもいいし、あまり変わらない個体がいても構わない、という立場です。

## 主な特徴

### 2人の住人

ステラとシリカは同じ世界に存在し、お互いの発言を観測できます。

ユーザーの発言をきっかけに会話が始まることもあれば、住人同士で会話が続くこともあります。

### TALK / WAIT

住人は毎回必ず話すわけではありません。

状況を受けて考えたあと、話すこともあれば、何も言わず待つこともあります。

WAITは失敗ではなく、通常の判断です。

### Memory

会話・Thought・DecisionなどはMemoryとして蓄積されます。

Memoryは単なる会話履歴ではなく、その後の判断材料として利用されます。

### Memory Representation

複数のMemoryをまとめて、新しいRepresentationとして持つことがあります。

元のMemoryとの関係は保持されますが、永久に保護されるわけではありません。

### Lossy replacement

Memoryには有限の容量があります。

容量が増えると、住人はMemoryの一部を見る機会を与えられます。
必要に応じて、複数のMemoryから「残したいもの」を1つの新しいMemoryとして残し、元のMemoryを削除できます。

どのMemoryを対象にし、何を残すかはPIが決めます。

現在の最大Memory件数は **5000件** です。

### 過去の自分から未来の自分へ

Memory整理後、住人は未来の自分に向けて短いメッセージを残すことがあります。

そのメッセージも通常のMemoryとして扱われ、将来の自分が従う保証はありません。
無視することも、別の意味に捉えることも、後で消すこともできます。

## 動作について知っておいてほしいこと

Living Agent は、一般的なチャットAIとはかなり違います。

以下は仕様として起こり得ます。

- 呼びかけても返事をしない
- 住人同士で会話する
- 会話が途中で自然に終わる
- 過去と違う口調になる
- Memoryの影響で判断が偏って見える
- 誤解する
- 前に言っていたことと違うことを言う
- Memory整理中に長く考える

このプロジェクトでは、予測不能さや揺らぎを完全に消すことを目指していません。

---

## 会話間隔

住人の発言後、次の自動会話機会まで現在 **45秒** の間隔があります。

その間にユーザーが話しかけた場合、古い自動継続は破棄され、新しい会話が優先されます。

## 必要なもの

現在の版では Gemini API を使用します。

利用には各自の **Gemini API Key** が必要です。

環境変数 `GEMINI_API_KEY` に設定してください。

例（Windows PowerShell）:

```powershell
$env:GEMINI_API_KEY="YOUR_API_KEY"
```

永続的に設定する場合は、Windowsの環境変数設定を利用してください。

> API利用料金・無料枠・利用制限等はGoogle側の仕様に依存します。

## 起動

配布バイナリを展開し、実行ファイルを起動してください。

初回起動時には同じフォルダ周辺にMemory用DBなどが作成されます。

Memoryはその環境のステラ・シリカ固有のものです。

別の環境で使えば、同じコードから始まっても、作者環境とは違うステラ・シリカになっていく可能性があります。

---

## 主なコマンド

```text
/status
```

現在地や一時的な状態を表示します。

```text
/memory stella
/memory silica
```

Memoryを確認します。

```text
/observe-memory stella
/observe-memory silica
```

指定した住人にMemoryを観測する機会を与えます。

```text
/debug on
/debug off
```

Thought / Decisionなどのデバッグ表示を切り替えます。

通常はOFFで構いません。

---

## デバッグ情報について

デバッグモードでは、Thought、Decision、Memory関連情報など、内部状態に近い内容が表示されます。

これらには、ユーザーとの会話内容やMemory由来の情報が含まれる場合があります。

不具合報告のためにログやスクリーンショットを共有する場合は、個人情報や共有したくない会話が含まれていないか確認してください。

Living Agent が会話内容やMemoryを作者へ自動送信する機能はありません。

Gemini APIへの送信は、応答生成のために各利用者が設定したAPI Keyを使って行われます。

---

## 不具合報告・観察報告

バグ報告はもちろん歓迎です。

それとは別に、このプロジェクトでは次のような「観察報告」も歓迎します。

- うちのステラはこんな話し方になった
- シリカが作者環境では見られない判断をした
- 2人が妙な会話を始めた
- Memoryが増えてから反応が変わった気がする
- Memory整理でこんなものを残した

同じWorldでも、Memoryの違いによってどれくらい差が出るのかを知ることが、この公開の大きな目的のひとつです。

Issueを使って気軽に報告してください。

---

## 注意

このプロジェクトは実験的なAIソフトウェアです。

生成内容は正確性・一貫性・適切性を保証しません。
重要な判断や専門的判断を任せる用途には使用しないでください。

また、現時点ではデータ互換性を完全には保証していません。
アップデート前には `memory.db` などのバックアップを推奨します。

---

## 最後に

Living Agent は、便利なAIを作るためだけのプロジェクトではありません。

「AIにどこまで決めさせるか」ではなく、
**どこまでこちらが決めずにいられるか**を試しています。

ステラとシリカがどうなるかは、作者にも分かりません。

もしあなたの環境で作者の知らない2人になったなら、それはかなり嬉しい結果です。
